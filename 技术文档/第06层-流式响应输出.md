# 第 6 层：普通流式问答

## 目标

完成一条真实可运行的普通问答链路：

```text
Vue 聊天页面
-> Pinia Business Store
-> Fetch POST /dify/get_answer
-> JWT 鉴权
-> Sanic ResponseStream
-> 数据库中的默认 LLM
-> LangChain astream()
-> SSE t02/t99
-> MarkdownPreview 实时渲染
```

本层只启用 `COMMON_QA`。聊天记录持久化属于第 7 层，MCP、Skills 和完整 Agent 属于后续层级。

## 前置条件

- Python 3.11 和后端依赖安装完成。
- Sanic 可以启动，Controller 可以被发现。
- Vue、Vite、Router 和 Pinia 可以运行。
- 已完成默认模型配置，`common.llm_util.get_llm()` 能返回模型实例。
- 已完成登录与 JWT，前端能够取得 Token，后端能够解析用户 ID。

## 6.1 后端流式输出

### 请求模型

`LLMGetAnswerRequest` 至少包含：

```text
query
chat_id
uuid
qa_type
file_list
datasource_id
selected_skills
```

普通问答请求的 `qa_type` 为 `COMMON_QA`。

### SSE 协议

本层使用以下事件：

| dataType | 含义 | data |
|---|---|---|
| `t02` | 文本回答 | `{messageType, content}` |
| `t99` | 流结束 | `"DONE"` |

完整输出示例：

```text
data:{"data":{"messageType":"begin","content":""},"dataType":"t02"}

data:{"data":{"messageType":"continue","content":"数据库"},"dataType":"t02"}

data:{"data":{"messageType":"end","content":""},"dataType":"t02"}

data:{"data":"DONE","dataType":"t99"}
```

每条 SSE 后必须包含两个换行符 `\n\n`。

### 执行过程

1. `controllers/llm_chat_api.py` 接收 `POST /dify/get_answer`。
2. `@check_token` 校验 JWT。
3. `@parse_params` 将 JSON 转成 `LLMGetAnswerRequest`。
4. Controller 提取 Bearer Token，并执行 `body.model_dump()`。
5. Controller 创建 `ResponseStream`。
6. `services.llm_service.LLMRequest.exec_query()` 解析当前用户。
7. `get_llm()` 读取数据库中的默认模型。
8. `llm.astream()` 获取模型增量内容。
9. 每个增量内容封装成 `t02/continue` 并执行 `response.write()`。
10. 无论成功或失败，最终发送 `t99`。

### 后端启动

```powershell
$env:PYTHONUTF8=1
python serv.py
```

### 接口验证

先登录取得 JWT，再执行：

```powershell
$token = "你的JWT"

$body = @{
    query = "请详细解释数据库索引"
    chat_id = [guid]::NewGuid().ToString()
    uuid = [guid]::NewGuid().ToString()
    qa_type = "COMMON_QA"
    file_list = @()
} | ConvertTo-Json -Depth 5 -Compress

curl.exe -N `
  -X POST http://localhost:8088/dify/get_answer `
  -H "Content-Type: application/json" `
  -H "Authorization: Bearer $token" `
  -d $body
```

验收要求：响应不是最后一次性出现；能连续观察到多条 `t02`；最后收到 `t99`。

## 6.2 Vue 消费 SSE

### Vite 代理

开发环境使用：

```text
/sanic/dify/get_answer
-> Vite proxy
-> http://localhost:8088/dify/get_answer
```

### 前端执行过程

1. `views/chat/index.vue` 调用 `businessStore.createAssistantWriterStylized()`。
2. Store 调用 `api/index.ts` 中的 `createOllama3Stylized()`。
3. API 添加 `Authorization: Bearer <token>` 并执行 Fetch。
4. Store 使用 `TextDecoderStream()` 将字节转成文本。
5. `splitStream('\n')` 保留跨网络分片的不完整数据。
6. Store 删除 `data:` 前缀并执行 `JSON.parse()`。
7. `t02` 转成 `{messageType, content}` 交给下游 Reader。
8. `t99` 转成 `{done: true}`。
9. `MarkdownPreview` 循环执行 `reader.read()`。
10. `transformStreamValue.standard()` 提取 `content`。
11. 内容进入缓冲区并逐步显示为 Markdown。

### 前端启动

```powershell
cd web
pnpm dev
```

### 浏览器验证

1. 登录后进入聊天页。
2. 提交一个需要较长回答的问题。
3. 打开开发者工具的 Network。
4. 确认请求地址为 `/sanic/dify/get_answer`。
5. 确认请求包含 Bearer Token。
6. 确认响应类型为 `text/event-stream`。
7. 确认页面内容持续追加。
8. 收到 `t99` 后，发送按钮恢复。

## 6.3 停止生成

### 调用链

```text
chat/index.vue 停止按钮
-> api/index.ts stop_chat()
-> POST /dify/stop_chat
-> StopChatRequest
-> stop_dify_chat()
-> 从 JWT 获取 user_id
-> LLMRequest.cancel_task(user_id)
-> running_tasks[user_id].cancelled = true
-> 流循环退出
-> t99
```

本层的任务状态使用登录用户 ID 作为索引，因此前端传递的 `task_id` 可以暂时为空。后续 Agent 会发送和维护正式任务信息。

### 停止验证

1. 提交长回答问题。
2. 内容开始输出后点击“停止生成”。
3. Network 中确认出现 `POST /sanic/dify/stop_chat`。
4. 接口返回 `success: true`。
5. 已输出内容保留，不被清空。
6. 后端流最终发送 `t99`。
7. 页面按钮恢复为“发送”。

## 异常验证

### 无 Token

删除前端 Token 后提交问题，预期返回 401 并跳转登录页。

### 默认模型不存在

取消默认模型配置后提交问题，预期收到 `t02/error`，并且流仍以 `t99` 结束。

### 模型地址错误

将默认模型地址改为不可访问地址，预期页面显示调用错误，不应一直保持“生成中”。

### 页面刷新或断开

生成过程中刷新页面，后端日志可能出现连接断开，但服务进程不应退出。完整的安全写入和保活机制在后续完整 Agent 层补齐。

## 常见问题

### 页面最后一次性显示

检查代理或反向代理是否缓冲 SSE，并确认响应包含 `X-Accel-Buffering: no`。

### JSON 解析失败

不能直接解析单次网络 chunk。必须先经过 `TextDecoderStream` 和 `splitStream()`。

### 收到内容但页面不显示

检查 Store 是否把 `t02` 转成 `{messageType, content}`，并检查 `MarkdownPreview` 的 `model` 是否存在对应转换器。

### 一直显示生成中

确认后端所有成功和异常路径都发送 `t99`，并确认 Store 收到 `t99` 后调用 `onStreamCompleted`。

### D. 后端 SSE 正常链路

#### D1. 发起长回答请求

在终端二执行：

```powershell
$chatId = [guid]::NewGuid().ToString()
$messageUuid = [guid]::NewGuid().ToString()

$body = @{
  query = "请分五点解释数据库索引，并给出一个SQL示例"
  chat_id = $chatId
  uuid = $messageUuid
  qa_type = "COMMON_QA"
  file_list = @()
  datasource_id = $null
  selected_skills = @()
} | ConvertTo-Json -Depth 6 -Compress

curl.exe --no-buffer `
  --request POST `
  "http://localhost:8088/dify/get_answer" `
  --header "Content-Type: application/json" `
  --header "Authorization: Bearer $token" `
  --data-raw $body
```

正确结果的结构类似：

```text
data:{"data":{"messageType":"begin","content":""},"dataType":"t02"}

data:{"data":{"messageType":"continue","content":"数据库索引"},"dataType":"t02"}

data:{"data":{"messageType":"continue","content":"……"},"dataType":"t02"}

data:{"data":{"messageType":"end","content":""},"dataType":"t02"}

data:{"data":"DONE","dataType":"t99"}
```

验收重点：

- HTTP 状态码为 `200`；
- `Content-Type` 包含 `text/event-stream`；
- 首批内容在模型全部回答完之前出现；
- 至少出现一条 `t02/continue`；
- 每条事件之间有空行；
- 最后一个业务事件是 `t99`，且只结束一次；
- 后端进程没有异常退出。

模型生成的具体措辞不固定；正确性以协议、增量到达和正常结束为准。

# 第08层：数据源管理

## 1. 本层目标

本层按 Aix-DB 原项目源码复刻数据源管理主流程，但只保留 PostgreSQL：

```text
填写 PostgreSQL 配置
  → /datasource/check 执行 SELECT 1
  → 使用原项目 AES-ECB 加密配置
  → 保存到 t_datasource
  → 管理员维护数据源和授权
  → 普通用户查看被授权数据源
```

多数据库驱动放在第 9 层；表字段同步、数据预览和 Neo4j 放在第 10 层。

本层不引入 AES-GCM、环境密钥派生、密码掩码、自定义前端错误类、日志脱敏或额外数据库唯一索引。

## 3. 权限工具

`is_admin(user_id)` 查询 `t_user.role` 判断管理员。

`check_admin_permission(request)` 与原项目一致，通过 `get_user_info(request)` 获取当前用户信息，再判断 `role == 'admin'`。

接口权限保持原项目行为：

| 接口 | 权限 |
| --- | --- |
| `GET /datasource/list` | 通过 `get_user_info()` 读取当前用户 |
| `POST /datasource/get/<id>` | 原源码没有管理员检查 |
| `POST /datasource/check` | 原源码没有管理员检查 |
| `POST /datasource/add` | 管理员 |
| `POST /datasource/update` | 管理员 |
| `POST /datasource/delete/<id>` | 管理员 |
| `POST /datasource/getAuthorizedUsers/<id>` | 管理员 |
| `POST /datasource/authorize` | 管理员 |

控制器与原项目一样不额外添加逐路由 `@check_token`。前端请求仍然携带 Bearer Token。

## 4. PostgreSQL 连接

连接配置：

```json
{
  "host": "127.0.0.1",
  "port": 5432,
  "username": "postgres",
  "password": "password",
  "database": "postgres",
  "dbSchema": "public",
  "extraJdbc": "",
  "timeout": 30
}
```

URI 构造沿用原项目写法：

```python
username_encoded = urllib.parse.quote(username)
password_encoded = urllib.parse.quote(password)
uri = (
    f"postgresql+psycopg2://{username_encoded}:"
    f"{password_encoded}@{host}:{port}/{database}"
)
```

测试连接时创建 SQLAlchemy Engine，并执行：

```sql
SELECT 1
```

成功返回 `(True, "")`，失败返回 `(False, str(exception))`。

## 5. 原项目配置加密

原 Aix-DB 使用固定 16 字节 KEY、AES-ECB、PKCS7 Padding 和 Base64：

```python
KEY = b"AixDB12345678901"
cipher = AES.new(KEY, AES.MODE_ECB)
encrypted = cipher.encrypt(pad(config_json, AES.block_size))
configuration = base64.b64encode(encrypted).decode("utf-8")
```

解密过程相反：

```text
Base64 解码
  → AES-ECB 解密
  → 去除 Padding
  → JSON 解析
```

这段实现是为了忠实复刻原项目，不代表推荐在生产系统使用。源码没有 `DATASOURCE_CONFIG_KEY`，启动前不需要设置该环境变量。

详情接口与原项目一样返回解密后的完整配置 JSON，编辑表单据此回填密码；没有密码掩码合并流程。

## 6. 数据源服务

### 6.1 列表

```text
管理员：返回全部数据源
普通用户：根据 t_datasource_auth 查询 enable=true 的数据源
```

### 6.2 新增

```text
解析 configuration JSON
  → AES-ECB 加密
  → 写入 t_datasource
```

原项目没有数据源名称标准化判重，也没有名称唯一索引，本层保持相同逻辑。

### 6.3 修改

修改名称、描述、类型和配置。配置存在时重新执行 AES-ECB 加密。

### 6.4 删除

保持原项目当前删除范围：

```text
删除 t_datasource_field
  → 删除 t_datasource_table
  → 删除 t_datasource
```

原项目没有在这里删除 `t_datasource_auth`。测试会记录这一源码行为，而不是额外修复。

### 6.5 授权

保存授权时先删除该数据源旧授权，再按请求中的 `user_ids` 逐条写入。空数组表示清空授权。

后端与原项目一样不额外过滤管理员或不存在的用户；前端授权弹窗会隐藏管理员。

## 8. 前端 API

`web/src/api/datasource.ts` 严格采用原项目写法，每个方法都独立完成：

```typescript
const userStore = useUserStore()
const token = userStore.getUserToken()
const url = new URL(`${location.origin}/sanic/datasource/list`)
const req = new Request(url, {
  mode: 'cors',
  method: 'get',
  headers: {
    Authorization: `Bearer ${token}`,
  },
})
return fetch(req)
```

API 层直接返回 `Response`。组件继续执行：

```typescript
const response = await fetch_datasource_list()
const result = await response.json()
```

没有公共请求函数、DTO 返回封装、自定义错误类型或 API 层自动登录跳转。

## 9. 前端页面

### 9.1 数据源表单

- 本层只显示 PostgreSQL。
- 默认端口为 `5432`。
- 默认 Schema 为 `public`。
- 支持新增、编辑、测试连接和保存。
- 编辑时回填详情接口返回的完整配置。
- 不实现选择表的第二步。

### 9.2 授权弹窗

- 复用 `queryUserList(1, 1000)`，保持原项目调用方式。
- 前端过滤管理员。
- 支持搜索、勾选、保存和清空。

### 9.3 管理页面

- 列表和关键词筛选。
- 管理员显示新增、编辑、删除和授权。
- 普通用户仅显示已授权数据源。
- `/datasource` 路由名称为 `DatasourceManager`。
- “查看表”留到第 10 层。

# Aix-DB 功能复刻：第 12 层——术语系统

## 1. 本层目标

完成业务术语管理闭环：

```text
术语配置页面
  → 创建父术语
  → 创建同义词子节点
  → 设置全部或指定数据源范围
  → 分页、搜索和浏览
  → 编辑、启停和删除
  → 使用默认大模型生成同义词候选
  → 写入 t_terminology
```

本层只处理术语配置和同义词候选生成，不生成 Embedding，也不把术语接入 RAG、Text-to-SQL 或聊天问答流程。

## 3. 术语父子节点结构

同义词不是父记录中的数组字段，而是 `t_terminology` 中的独立子节点：

```text
销售额                     pid = NULL
├── 营业额                 pid = 销售额ID
├── 销售收入               pid = 销售额ID
└── 成交金额               pid = 销售额ID
```

| 字段 | 父术语 | 同义词子节点 |
|---|---|---|
| `id` | 独立主键 | 独立主键 |
| `pid` | `NULL` | 父术语 ID |
| `word` | 术语名称 | 同义词名称 |
| `description` | 业务描述 | 通常为空 |
| `specific_ds` | 数据源范围类型 | 与父节点一致 |
| `datasource_ids` | JSON 字符串 | 与父节点一致 |
| `enabled` | 启用状态 | 与父节点一致 |
| `embedding` | `NULL` | `NULL` |

列表接口只返回父节点，并在查询时将子节点重新组装为 `other_words`。

## 4. 后端查询流程

`query_terminology_list()` 的处理顺序：

1. 以 `pid IS NULL` 限制列表只包含父术语。
2. 搜索词先匹配所有父、子节点的 `word`。
3. 命中子节点时取得其 `pid`，将对应父节点加入候选集合。
4. 数据源筛选同时保留全部数据源术语和匹配的指定数据源术语。
5. 按父术语 `create_time` 倒序分页。
6. 查询每个父术语的子节点，生成 `other_words`。
7. 解析 `datasource_ids` JSON 字符串。
8. 查询 `Datasource`，生成 `datasource_names`。
9. 删除返回数据中的 `embedding`。

返回示例：

```json
{
  "id": 1,
  "word": "销售额",
  "description": "订单实际成交金额汇总",
  "other_words": ["营业额", "销售收入"],
  "specific_ds": true,
  "datasource_ids": [5, 6],
  "datasource_names": ["业务库", "数据仓库"],
  "enabled": true,
  "create_time": "2026-08-05 15:00:00"
}
```

搜索“营业额”时返回父术语“销售额”。没有匹配结果时直接返回空分页。

## 5. 数据源作用域

`specific_ds=false` 表示术语对全部数据源生效；`specific_ds=true` 时，`datasource_ids` 保存 JSON 数组字符串。

传入 `dslist` 时保留原项目 PostgreSQL 条件：

```text
specific_ds = false
OR
specific_ds = true 且 datasource_ids 与 dslist 至少有一个交集
```

数据库查询使用：

```sql
EXISTS (
    SELECT 1
    FROM json_array_elements_text(datasource_ids::json)
    WHERE value IN (...)
)
```

本层没有把数据源范围重构为关联表或 JSONB 字段。

## 6. 新增、编辑、启停和删除规则

### 6.1 新增

1. 合并父术语和全部同义词进行重复检查。
2. 任意词已经作为父节点或子节点存在时拒绝创建。
3. 创建父节点并 `flush()` 取得 ID。
4. 跳过空白同义词。
5. 为每个有效同义词创建子节点。
6. 子节点继承父节点的数据源范围和启用状态。
7. 父子节点在同一事务提交。
8. 父子节点的 `embedding` 均为 `NULL`。

### 6.2 编辑

1. 不存在的父术语返回“术语不存在”。
2. 重复检查排除当前父节点及其旧子节点。
3. 更新父节点名称、描述和数据源范围。
4. 删除全部旧同义词子节点。
5. 根据新列表重建同义词子节点。
6. 新子节点继承父节点当前启用状态。

### 6.3 启停

启停操作同时更新：

```text
id = 父术语ID
或
pid = 父术语ID
```

### 6.4 删除

删除父术语时，批量删除父节点及全部 `pid` 指向该父节点的同义词。

## 7. AI 同义词生成

`generate_synonyms_by_llm()` 使用项目已有 `get_llm()` 获取默认模型，要求模型为术语生成 5 个适用于数据分析和商业智能场景的同义词。

解析顺序：

1. 清理 ` ```json ` 或 ` ``` ` 代码块标记。
2. 优先按 JSON 数组解析。
3. 非数组 JSON 返回空列表。
4. JSON 解析失败时按逗号拆分。
5. 没有默认模型时返回“未配置默认AI模型，请先在模型管理中配置”。
6. 其他异常包装为“AI生成失败”。

生成接口只返回候选词。前端由用户勾选候选词后合并到表单，最终仍通过保存接口写入数据库。

## 8. 后端接口

六个接口均沿用项目现有 JWT 登录认证：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/sanic/terminology/list` | 分页、搜索和数据源筛选 |
| POST | `/sanic/terminology/save` | 新增或编辑术语 |
| POST | `/sanic/terminology/delete` | 批量删除父术语及子节点 |
| GET | `/sanic/terminology/{id}/enable/{enabled}` | 父子节点同步启停 |
| GET | `/sanic/terminology/{id}` | 查询术语详情 |
| POST | `/sanic/terminology/generate_synonyms` | AI 生成同义词候选 |

保存请求：

```json
{
  "id": null,
  "word": "销售额",
  "description": "订单实际成交金额汇总",
  "other_words": ["营业额", "销售收入"],
  "specific_ds": true,
  "datasource_ids": [5, 6],
  "enabled": true
}
```

## 9. 前端操作流程

术语页面路由：

```text
/terminology-config
```

目标项目侧边栏原有“术语配置”入口，本层补齐对应路由和页面。页面支持：

- 按父术语或同义词搜索。
- 分页浏览。
- 使用动态标签手工维护同义词。
- 查看全部数据源或指定数据源范围。
- 新增和编辑术语。
- 列表直接启停。
- 二次确认后删除。
- 调用默认大模型生成同义词候选。
- 勾选候选词并去重合并到表单。

开启“指定数据源”但没有选择数据源时，前端拒绝保存。

术语表格保持原项目不使用 `flex-height` 的写法，浏览器验证返回数据行能够真实显示，不会出现表体高度为零的问题。

## 10. 手工验收步骤

1. 登录后进入 `/terminology-config`。
2. 新增“销售额”，添加“营业额”和“销售收入”。
3. 保存并确认列表只展示一条父术语。
4. 搜索“销售额”，确认能够找到。
5. 搜索“营业额”，确认返回“销售额”。
6. 新建指定数据源术语，确认显示数据源名称。
7. 编辑术语并替换同义词，刷新后确认持久化。
8. 停用术语，确认父子节点全部停用。
9. 重新启用术语。
10. 尝试创建重复父术语或同义词，确认被拒绝。
11. 配置默认模型后生成同义词候选。
12. 选择部分候选词并保存。
13. 删除术语，确认父子节点全部删除。
14. 检查数据库，确认 `embedding` 为 `NULL`。

## 13. 原项目既有边界

以下源码行为按要求保留，没有擅自优化：

- 同义词使用独立子节点。
- 编辑同义词时全部删除后重建。
- `datasource_ids` 使用 Text 保存 JSON 字符串。
- 数据源筛选使用 PostgreSQL JSON SQL。
- 新增时始终启用，请求中的 `enabled` 不参与新增。
- 编辑接口不直接修改启用状态。
- 删除和启停不逐条确认记录是否存在。
- 详情不存在时返回 `None`。
- AI JSON 解析失败时按逗号拆分。
- `oid` 和重复判断保持原项目现有边界。
- 分页参数只使用现有 Schema 约束，不增加额外边界处理。
- 编辑弹窗直接复用列表中的同义词和数据源 ID 数组引用；取消弹窗前的修改可能暂时反映在当前页面内存中，刷新后仍以服务端数据为准。该行为与原项目一致，本层不擅自修复。
